# Доступність і токени

Перевірки етапу 13. Що перевіряє автотест, а що лишається для ручної перевірки на пристрої.

## Правила

| Правило | Значення | Де закріплено |
|---|---|---|
| Розмір тексту | не менше 16px (`--font-size-sm: 1rem`), основний текст 17px як в iOS | `src/styles/tokens.css`, тест `tokens.test.ts` |
| Контраст тексту AA | не менше 4,5:1 | тест `tokens.test.ts` (обчислення за формулою WCAG) |
| Рамки полів і фокус | не менше 3:1 (`--color-control-border`, `--color-focus`) | тест `tokens.test.ts` |
| Зона дотику | не менше 44px (`--tap-target`) | `tokens.css`, тест; стилі кнопок, пунктів меню, клітинок календаря |
| Підписи кнопок-іконок | `aria-label` | кнопка «×» у списку складу має підпис; інші іконки це декор (`aria-hidden`) поруч із текстом |
| Видимий фокус | контур 3px | `src/styles/reset.css` (`:focus-visible`) |
| Статус не лише кольором | текст, форма, позначка | вкладка в нижній навігації (смуга + жирний), статуси мають слова й іконки, календар підкреслює сьогодні, маркери графіка різні за формою |
| Рух | `prefers-reduced-motion` вимикає анімації | `reset.css` |
| Мова | `lang="uk"` | `index.html` |
| Клавіатура | усі дії це `button` і `a`, власних обробників кліків на `div` немає | перегляд коду |

## Контраст токенів (обчислено, тимчасовий дизайн у стилі iOS)

| Пара | Контраст |
|---|---|
| Текст `#1c1c1e` на фоні `#f2f2f7` / білому | 15,3 / 17,0 |
| Приглушений текст `#636366` | 5,4 / 6,0 |
| Основний колір `#0062cc` (посилання, акцент) | 5,2 / 5,8; на світло-синьому `#e8f0fe` 5,1 |
| Білий текст на кнопці `#0062cc` | 5,8 |
| Рамка поля `#86868b` | 3,3 / 3,6 |
| Фокус `#0062cc` | 5,2 / 5,8 |

Системний синій iOS (`#007aff`) на білому дає лише 4,0:1, тому взято темніший `#0062cc`.

Звичайні декоративні рамки карток (`--color-border`) мають низький контраст свідомо: вони лише групують блоки, а межі полів і кнопок використовують `--color-control-border`.

## Токени: що обходить `tokens.css`

Тест `tokens.test.ts` падає, якщо в `src` з'являється колір (hex, rgb, hsl) поза `tokens.css`, колір у вбудованому `style`, або `font-size` не з токена. Винятки:

| Місце | Чому |
|---|---|
| `src/lib/image/browserImage.ts`: `fillStyle = '#ffffff'` | білий фон полотна під час стиснення фото (дані зображення, не інтерфейс) |
| `vite.config.ts`: `theme_color`, `background_color` у manifest | manifest не читає CSS-змінні; значення збігаються з `--color-surface` і `--color-bg` |
| `index.html`: `<meta name="theme-color">` | те саме |
| `public/`: іконки, `favicon.svg` | растрові й векторні картинки |

## Що змінено на етапі 13

- `--font-size-sm` з 14px до 16px; підписи осей графіка (було 10px) тепер теж 16px.
- Нова змінна `--color-control-border`: усі поля, вибір, чипи й кнопки з рамкою 2px переведено на неї (було `#d6d6d0`, 1,5:1).
- Нижня навігація: висота `--nav-height` 72px, довгі підписи переносяться; горизонтальні відступи зменшено.

## Як запустити Lighthouse

1. Зберіть і запустіть продакшен-версію: `npm run build && npm run preview`.
2. Відкрийте адресу з терміналу в Chrome, F12 → вкладка Lighthouse.
3. Режим Mobile, категорії Accessibility і PWA, натисніть Analyze.
4. Ціль: Accessibility не менше 90. Звіт збережіть у `docs/quality/lighthouse-report.html` (кнопка «Save as HTML» у меню звіту) і запишіть оцінку нижче.

## Ручна перевірка (на телефоні)

- нижня навігація на екрані 360px: усі п'ять підписів читаються без обрізання;
- кожна сторінка керується клавіатурою (Tab, Enter, Esc у вікнах);
- читання екранним диктором (TalkBack або VoiceOver) для тесту, результату перевірки й графіка;
- збільшення шрифту системи до 130 %: нічого не накладається.
