# PWA: встановлення, офлайн, оновлення

## Що налаштовано

- `manifest.webmanifest` створюється збіркою: назва, `short_name`, `display: standalone`, `lang: uk`, кольори, іконки 192 і 512 та maskable 512 (`public/`).
- Service worker `sw.js` створюється збіркою (Workbox). Він зберігає файли застосунку (js, css, html, іконки; контент із `src/content/data/*.json` уже вбудований у js), тому застосунок відкривається без інтернету.
- Запити до `/api/` **ніколи** не кешуються (правило `NetworkOnly`) і не підміняються сторінкою-запасною (`navigateFallbackDenylist`).
- Нова версія не вмикається мовчки: зʼявляється банер «Доступна нова версія» з кнопками «Оновити» й «Пізніше».
- Service worker реєструється лише в продакшен-збірці (`import.meta.env.PROD`); у `npm run dev` його немає.
- Іконки поки тимчасові (абстрактне кільце, без бренду й літер). Замінити на затверджені перед публічним релізом: файли в `public/` з тими самими іменами.

## Як перевірити локально

```
npm run build
npm run preview
```

Адреса `http://localhost:4173` (service worker дозволений на `localhost`). Для телефону потрібен HTTPS, тобто розгортання (або тунель).

1. Відкрити в Chrome → F12 → Application: **Manifest** без помилок, **Service Workers** зі статусом activated.
2. Network → Offline, оновити сторінку: застосунок відкривається.
3. У Offline: тест, догляд, довідник, щоденник працюють; сканування фото каже «Немає звʼязку» й пропонує ввести склад вручну.
4. Application → Cache Storage: у кеші немає жодного запиту з `/api/`.

## Встановлення на Android (Chrome)

1. Відкрити розгорнуту адресу в Chrome.
2. Меню (три крапки) → «Установити застосунок» (або «Додати на головний екран»); Chrome може запропонувати це сам.
3. Іконка зʼявиться на екрані, застосунок відкривається без адресного рядка (режим standalone).

## Встановлення на iOS (Safari)

Safari не показує підказки про встановлення, це нормально.

1. Відкрити адресу в Safari.
2. Кнопка «Поділитися» → «На початковий екран».
3. Застосунок відкривається без елементів Safari.

## Як перевірити оновлення

1. Розгорнути версію A, відкрити, дати service worker встановитись.
2. Змінити щось видиме, підняти `version` у `package.json` і `src/content/data/version.json`, розгорнути версію B.
3. Закрити й знову відкрити застосунок (або оновити). Має зʼявитись банер «Доступна нова версія».
4. «Оновити»: сторінка перезавантажується вже з версією B (версію видно на екрані «Про застосунок»). «Пізніше»: банер зникає, стара версія працює.

Якщо після оновлення видно старий вміст: у Chrome F12 → Application → Service Workers → Update або Unregister; перевірити, що `sw.js` віддається з `Cache-Control: max-age=0, must-revalidate` (`vercel.json`).

## Що не перевірено

Встановлення на реальних Android і iOS, поведінка офлайн на телефоні, оновлення між двома розгорнутими версіями, `curl -I` заголовків на розгорнутій адресі: розгортання й телефона в середовищі розробки не було.
