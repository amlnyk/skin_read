# API.md: контракти серверних функцій

## Загальне
- Той самий домен, відносні шляхи /api/... Усі функції приймають лише POST з
Content-Type: application/json і відповідають application/json.

- Схеми запитів і відповідей живуть у src/schemas/api.ts і використовуються і
клієнтом, і сервером.
- Успішна відповідь містить apiVersion (зараз 1). Зміна контракту, що ламає
сумісність, піднімає версію.
- Помилка завжди має вигляд { "error": { "code": "КОД", "message": "загальний
текст без деталей реалізації" } }.
- Порядок обробки: метод, Origin, ліміти, тип вмісту, розмір тіла, парсинг JSON, zod,
перевірка вмісту (байти файлу), виклик ШІ, zod відповіді, відповідь. Ліміти
перевіряються до будь-якого виклику ШІ.
- Заголовки відповіді: Cache-Control: no-store, X-Content-Type-Options:
nosniff. Access-Control-Allow-Origin зі значенням «*» заборонений; запити з
недозволеним Origin отримують 403.
- Логи містять лише код помилки, випадковий id запиту, тривалість і факт
спрацювання ліміту. Зображення, тексти складу й IP у відкритому вигляді не
логуються (для ліміту IP зберігається лише хеш).

## POST /api/analyze-label
Запит: { imageBase64: string (без префікса data:), mediaType: 'image/jpeg' |
'image/png' | 'image/webp' }
Обмеження: розмір після декодування до 1,5 МБ; тип перевіряється за першими
байтами файлу.
Відповідь 200: { apiVersion: 1, productName: string|null, brand: string|null,
categoryGuess: string|null, ingredientsText: string|null, language: string,
confidence: число від 0 до 1 }
Якщо ingredientsText порожній чи null: 422 NO_INGREDIENTS_FOUND.

## POST /api/simplify (необов'язково, етап 12)
Запит: { componentId: string (id з контенту), text: string (до 1000 символів)
}
Відповідь 200: { apiVersion: 1, text: string (до 1500 символів) }

## Коди помилок
| HTTP | Код | Коли | Що показує клієнт |
|---|---|---|---|
| 400 | BAD_REQUEST | не JSON, не пройшла схема, порожнє тіло | «Не вдалося обробити запит» і ручне введення |
| 405 | METHOD_NOT_ALLOWED | не POST; заголовок Allow: POST | загальне повідомлення про помилку |
| 403 | ORIGIN_NOT_ALLOWED | Origin не зі списку ALLOWED_ORIGINS | загальне повідомлення про помилку |
| 413 | IMAGE_TOO_LARGE | понад 1,5 МБ після декодування | «Фото завелике, спробуй ще раз» |
| 415 | UNSUPPORTED_FORMAT | тип не з дозволених або байти не відповідають типу | «Формат не підтримується» |
| 422 | NO_INGREDIENTS_FOUND | склад не знайдено на фото | підказки щодо зйомки |
| 429 | RATE_LIMITED | ліміт на IP чи добовий; заголовок Retry-After | «Забагато запитів, спробуй пізніше або введи склад вручну» |
| 500 | INTERNAL | непередбачена помилка | загальне повідомлення |
| 502 | AI_BAD_RESPONSE | відповідь моделі не JSON чи не пройшла схему | «Не вдалося розпізнати» і ручне введення |
| 503 | AI_UNAVAILABLE | модель недоступна чи вичерпано витрати | «Сервіс недоступний» і ручне введення |
| 504 | TIMEOUT | модель не відповіла за таймаут (на сервері менший за клієнтські 20 с) | «Довго чекаємо» і ручне введення |

## Змінні середовища сервера
Лише в налаштуваннях хоста (Production, Preview, Development окремо), ніколи в git і ніколи з префіксом `VITE_`.

| Змінна | Призначення | За замовчуванням |
|---|---|---|
| ANTHROPIC_API_KEY | ключ ШІ; без нього функція відповідає 503 AI_UNAVAILABLE | немає |
| ANTHROPIC_MODEL | назва моделі; без неї 503 | немає |
| ALLOWED_ORIGINS | дозволені origin через кому, напр. `https://my-app.example`, `https://*.vercel.app` | порожньо: усі запити 403 |
| RATE_LIMIT_PER_HOUR | запитів на IP за годину | 10 |
| DAILY_LIMIT | запитів на добу всього | 200 |
| MODEL_TIMEOUT_MS | таймаут виклику моделі | 15000 |

## Локальний запуск і перевірка
1. `vercel dev` (потрібен Vercel CLI; або будь-який хост, що запускає `api/analyze-label.ts` як функцію з Web-стандартним обробником).
2. Змінні: `vercel env add ANTHROPIC_API_KEY` (так само інші), або файл `.env.local` (ігнорується git).
3. Перевірка `curl` з малим JPEG (потрібен заголовок Origin зі списку `ALLOWED_ORIGINS`, інакше 403):
```
curl -i -X POST http://localhost:3000/api/analyze-label \
  -H "Content-Type: application/json" \
  -H "Origin: http://localhost:3000" \
  -d "{\"imageBase64\": \"<base64 малого jpeg>\", \"mediaType\": \"image/jpeg\"}"
```
Очікуване: 200 із JSON; для фото понад 1,5 МБ 413 IMAGE_TOO_LARGE; для фото без складу 422 NO_INGREDIENTS_FOUND; без Origin 403.
4. Платформи мають власний ліміт тіла запиту (у Vercel 4,5 МБ). Клієнт стискає фото до 1,5 МБ, base64 дає близько 2 МБ, тож ліміт не заважає.
5. Після збірки перевір, що ключа немає в клієнті: у `dist` не має бути рядків `ANTHROPIC` і `sk-ant`.

## Ліміти й надійність
Ліміти в пам'яті екземпляра функції: це обмеження навмання, не гарантія (див. `docs/decisions.md`, Етап 11, п. 7). Для надійності потрібне спільне сховище (Upstash Redis чи Vercel KV): реалізується інтерфейс `RateLimiter` у `api/_lib/rateLimit.ts`.
